camera time sync

Local app to control time-synced video recording across multiple iPhones (web client), upload clips to a host computer, and synchronize them in post for 2D pose estimation / 3D reconstruction.

1 · Overview

A single host process (your Mac) serves a browser-based control UI and a phone capture page over the local network. Each iPhone records independently in Safari; the host coordinates a synchronized start and a shared clap, then aligns the clips offline. The design mirrors OpenCap (PLOS Comput Biol 2023): phones record independently and real synchronization is recovered in post-processing, not at capture time.

Hard constraints (why it is built this way)

  • Client = web/PWA in iOS Safari (no native app). Safari cannot expose per-frame hardware capture timestamps, cannot lock fps, and stops recording on screen lock. MediaRecorder output is variable-frame-rate (VFR).
  • Real sync accuracy comes from the post-hoc layer. All streams are treated as VFR and resampled to a common timeline.
  • HTTPS is mandatory — iOS blocks getUserMedia outside a secure context, even on the LAN. A locally-trusted cert (mkcert) must be installed on each phone.
  • Minimal stack: one app.py (aiohttp) = HTTPS + WebSocket hub + upload-to-disk; vanilla HTML/JS UIs; filesystem only — no database, framework, or build step. Offline analysis in sync.py / calibrate.py.

2 · Architecture

Components

  • app.py — aiohttp host: serves pages, runs the WS hub (registry, clock-sync, synchronized trigger, live preview relay), accepts chunked uploads.
  • web/control/ — control UI (pairing QR, config, session metadata, roster, live preview, reports panel, host status).
  • web/capture/ — phone capture page: getUserMedia + MediaRecorder (video/mp4), per-frame timestamps via requestVideoFrameCallback, wakeLock, clap cue, low-rate preview.
  • sync.py — post-hoc alignment (clap cross-correlation + timestamps + ffmpeg).
  • calibrate.py — OpenCap-style camera calibration (checkerboard / reference object).
  • session_report.py — per-recording HTML report (sync verdict + clap diagnostic).
  • report.py — overall procedure report across all steps.

Data flow

phones (Safari)
  │ WSS register + clock-sync
  │ ◄── synchronized start (T0) + clap cue
  ▼ record locally (VFR)
  │ HTTPS chunked upload
  ▼
host disk: sessions/<id>/<cam>/
  ▼ sync.py (clap x-corr → CFR)
aligned clips + offsets.json + report.html
  ▼
opencap-core / Pose2Sim → 3D

Shared time base = host wall-clock (ms). Phones estimate their offset to it via an NTP-like ping/pong.

3 · Running (UI-first, minimal terminal)

  1. One-time cert setup: install mkcert on the Mac (brew install mkcert nss → mkcert -install), then trust the mkcert root CA on each iPhone (AirDrop rootCA.pem → install profile → Settings → General → About → Certificate Trust Settings → enable full trust).
  2. Launch: double-click start.command in Finder. It creates the venv on first run, starts the host, opens the control UI, and auto-refreshes the TLS cert if the LAN IP changed (no setup_certs.sh re-run). Default: https://<LAN-IP>:8443/.
  3. Pair phones: on each iPhone (same Wi-Fi), open Safari and scan the QR in the control UI → allow camera & mic. The phone appears in the Cameras roster with a live clock offset.
  4. Record: set config → Push config → fill session metadata → Start (synchronized) → clap once at the cue → Stop. Clips upload automatically.
  5. Report: in the Recordings & sync reports panel, click View report.

Network note: campus/eduroam Wi-Fi often blocks device-to-device traffic. If phones can't reach the host, use one iPhone's Personal Hotspot for the Mac + the other phone.

6 · Synchronization method (Step 8)

Layered, robust-first. sync.py ingests a session and writes sessions/<id>/sync/offsets.json + CFR clips under sync/aligned/:

  1. Audio clap cross-correlation (primary): the single physical clap is recorded by every phone's mic; cross-correlating the rectified, smoothed audio envelopes (1 kHz) gives a sharp, sub-frame relative offset. Uses the whole transient pattern, so it is robust to echoes / multiple claps.
  2. Per-frame timestamp offset (independent prior / fallback): first server-clock stamp per camera from frames.json. Used as a sanity cross-check against the audio result, and as fallback when audio is unusable.
  3. Render: ffmpeg resamples each VFR clip to a common CFR and trims so the claps coincide.
  4. Verify (--verify): re-extracts audio from the aligned clips and re-measures the residual inter-camera offset → the headline accuracy number.

Optional, not required for temporal alignment: keypoint-velocity cross-correlation (OpenCap) as a secondary refinement — documented plug-in point in sync.py.

└─ report.html            per-recording sync + clap diagnostic (served at /report)

8 · Reports

Per-recording (session_report.py → report.html, opened from the UI): a sync-error verdict vs the frame period ≤ ½ frame = sub-frame ≤ 1 frame = adequate, the clap-detection diagnostic (audio envelopes + normalized cross-correlation curve, inline SVG), a Step-4 capture table (frames, monotonic timestamps, effective fps), and the independent audio-vs-timestamp cross-check.

Overall procedure report (report.py → report/procedure_report.html): every step, its validation gate and outcome, the latest automated test run, sync-accuracy plots, and the failure/history log.

9 · Calibration (Step 7b)

calibrate.py recovers per-camera intrinsics + extrinsics for 3D triangulation:

SubcommandMethod
intrinsicsCheckerboard findChessboardCorners + calibrateCamera.
extrinsics-boardShared checkerboard via solvePnP (primary).
extrinsics-objectReference object / known 3D control points, manual point-picking (alternative).

Output is opencap-core-compatible so 3D reconstruction (DLT triangulation → OpenSim) runs in opencap-core / Pose2Sim — not reimplemented here.
